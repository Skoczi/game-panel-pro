# Per-server SFTP

SFTP is opt-in in server Settings, before Clone and Delete. Host is an assigned game IPv4 explicitly allowed by the node's SFTP configuration. There is no node management IP fallback. Login is the immutable runtime UUID, so equal local numeric IDs on different nodes cannot be confused.

Native servers expose only `data/serverfiles`; other supported managed servers expose their `data` mount. The virtual filesystem blocks traversal and symlink escapes. SSH commands, FTP, WebDAV and the web client are disabled. Passwords are generated, returned once, hashed by SFTPGo, and excluded from the durable agent response journal. The browser does not persist passwords. Rotation/disable disconnect sessions; deletion revokes the account before deleting files.

Reading status requires `fs.read`. Changing access requires all of `sftp.manage`, `fs.read`, `fs.write`. The Server administrator preset includes these; existing grants are not changed. This is a shared server credential: removing a panel member or logging out does not revoke a password already copied into an SFTP client. Rotate it when removing someone's access. Disable SFTP before maintenance requiring an exclusive offline snapshot; active external transfers do not participate in the panel's file-operation lock.

## WAW2 service

- SFTPGo 2.7.6 pinned to image digest in `deploy/tools/eserv_sftp_setup.py`.
- Game IPs 51.83.150.145–149, TCP 2023. Existing port 2022 is occupied by Wings and was left unchanged.
- No listener on the node management IP; REST API is only on a separate Docker network shared with the panel agent.
- UID/GID 1000, read-only container root, dropped capabilities, no-new-privileges, resource/log limits.
- `/srv/gamepanel-agent/data/sftp-service.json` is root-only and contains private API credentials. Never copy it to documentation or client responses.
- `/srv/gamepanel-agent/sftp/` stores compose/bootstrap files and the original backend compose and servers-root ACL. The servers root grants UID 1000 traversal only, without directory listing.
- FR1/WAW1 have no dedicated game IP configured for this service; their UI reports SFTP unavailable.

## Validation

- Full Linux backend suite: 270 tests passed before the final additional revocation regression; focused SFTP suite: 6 tests passed.
- Isolated real HTTP/SQLite acceptance verifies permission combinations, other-server denial, no terminal privilege and existing session/MFA/role checks.
- Frontend: 65/66 tests initially passed; the failure caught SFTP between Clone and Delete. Moving it above Clone fixed the focused regression. Both SFTP UI tests pass, including one-time secrets and mobile overflow.
- External Paramiko test over the actual game IP: pinned host key, read/write/rename/delete; sibling/symlink/absolute-path isolation; no SSH command; password rotation and disable both disconnect active sessions; old passwords rejected; node management address does not accept port 2023.
- Temporary protocol-test accounts/files were removed. Game containers were not restarted during provisioning.

## Operations and rollback

The setup helper requires explicit node and game IPs and excludes the management IP. It does not create game accounts. `--resume` preserves service credentials and state; review changes before rerunning. Passwords stay out of terminal output and test logs.

Panel/agent deployment uses the existing per-host image patch helpers and SQLite/compose snapshots. To withdraw SFTP, disable accounts first, then stop the separate `eserv-sftp` compose service. Preserve its state and host keys for recovery; use the saved ACL and backend compose only after checking for later changes. Do not restore the old compose blindly over newer deployments.
